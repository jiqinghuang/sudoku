# 数独 · 逐步解 (Sudoku Step Solver)

> **在线试玩：<https://jiqinghuang.github.io/sudoku/>** — 打开即用，无需安装

一个「会讲人话」的数独求解器。它不直接甩给你答案，而是像一位耐心的老师：
每填一格都告诉你**填了什么、凭什么能填**。跟着它把一盘棋推完，你也就学会了数独的解题思路。

## 它能做什么

- **逐步推理**：每一步都有中文理由——哪一格、填什么、凭什么；同时高亮涉及的行/列/宫、参与推理的格子、被排除的候选，一眼看懂
- **批量填入（默认）**：同一种技巧下互不依赖的明显格一次填完（单步最多 4 格、最显眼的先讲），复杂推理单独成步；想像老师带着一格一格走，勾选「一步一格」即可，两种粒度用的是同一次推理结果，终盘完全一致
- **批量步可折叠**：一步包含多格时，逐格理由默认只展开第一条，其余点开看；「展开逐格理由」一键全展开
- **前进 / 后退 / 自动播放**：像看视频一样回放整个解题过程，随时暂停、点击任意一步跳转
- **四种难度出题**：简单 / 中等 / 困难 / 专家，按解题实际用到的最高技巧定级（不是线索数），每道题都保证唯一解
- **两种开题方式**：点击选格后用键盘 `1`–`9` 直接填数，或一键随机出题（四档难度，保证唯一解）
- **慢活不卡界面**：求解与出题在后台线程（Web Worker）执行，界面始终可交互；不支持的场合（如双击本地打开）自动回退同步执行，功能不受影响
- **一屏不滚动**：整个界面适配视口高度，只有右侧面板内部滚动，游戏体验不被页面滚动打断
- **有错早知道**：题目冲突、无解、多解都会给出通俗的解释，而不是给出一个错误答案

## 它懂哪些技巧

| 技巧 | 一句话解释 |
| --- | --- |
| 唯一候选数 | 一格被 8 个数字堵死，只剩一个能填 |
| 行/列/宫唯一 | 某个数字在一个单元里只剩一格能放 |
| 区块摒除 | 宫里的数字被挤进同一行/列，宫外同行/列的同数字候选全部排除 |
| 显性数对/三数组 | k 个格子的候选合起来只有 k 个数，这几个数被它们"承包" |
| 隐性数对/三数组 | k 个数字只落在同样 k 个格子里，这 k 格必须腾位装它们 |
| X-Wing | 两行两列四角互锁成矩形，两条边上的同数字候选全部排除 |
| 试填 + 回溯 | 技巧用尽时做假设并自动试错——**明确标黄提醒，不冒充逻辑** |

高阶技巧（Swordfish、XY-Wing 等）暂未实现；遇到推不动的题，它会诚实告诉你此步是试填。

> 一步一格模式下，一步只讲**一种**技巧：同一盘面下先用唯一候选数推完，再轮行/列/宫唯一，
> 不会把两种技巧的结论混在同一步里。

## 快速开始

**方式一 · 在线玩（推荐）**
打开 <https://jiqinghuang.github.io/sudoku/>，点「随机出题 → 简单」，再一步步按「下一步」看推理。

**方式二 · 本地离线玩**
下载本仓库后**双击 `index.html`** 即可——纯静态页面，零依赖，不需要安装任何东西。
（浏览器不允许 `file://` 页面创建 Worker，此时求解自动退回主线程同步执行，功能完全不受影响。）

**方式三 · 开发 / 跑测试**

```bash
npm install        # 安装 TypeScript 编译器（唯一的 devDependency，运行时零依赖）
npm test           # 编译 src/*.ts → dist/*.js，并跑全部自动化测试
npm run typecheck  # 仅类型检查
npm run build      # 仅编译（dist/ 随仓库提交，改完 src 请重新编译，CI 会校验同步）
```

## 项目结构

| 文件 | 说明 |
| --- | --- |
| `index.html` | 界面（HTML + CSS），加载 `dist/solver.js` 与 `dist/ui.js`（后者按需再派生 `dist/worker.js`） |
| `src/solver.ts` | 求解器：位运算 + 约束传播 + 唯一解搜索 + 中文推理文案；`mode:'fast'/'teach'` 决定步骤粒度 |
| `src/ui.ts` | 界面逻辑：棋盘渲染（含无障碍语义）、步骤回放、一步一格开关、逐格理由折叠、取消按钮、键盘 / 数字键盘 / 随机题 |
| `src/worker.ts` | 求解 Worker：solve / 出题在后台线程执行，避免界面卡顿（`mode` 原样透传） |
| `src/test.ts` | 求解器测试：正确性、回放一致性、边界、性能、粒度模式与 Worker 消息协议 |
| `src/uitest.ts` | UI 接线测试：用最小 DOM stub 执行真实界面脚本（同步路径 + 注入假 Worker 的降级路径） |
| `dist/` | tsc 编译产物（随仓库提交，线上加载的就是它） |
| `tsconfig.json` | strict 模式 TypeScript 配置 |
| `.github/workflows/ci.yml` | CI：类型检查 + 全量测试 + dist 同步校验 |

架构一句话：**TypeScript 源码 → tsc 编译 → 纯静态产物**。同一份求解器跑在浏览器（主线程与 Worker）和 Node 测试里；Worker 构造失败、脚本 404 或运行出错时自动退回主线程，两条路径行为一致，且任何失败都会恢复按钮可交互、如实报错而不是卡住。

> 发布提示：`index.html` 里 `dist/*.js` 带 `?v=` 版本号，GitHub Pages 对静态资源有 10 分钟缓存；
> 每次改了 `dist` 就顺手把版本号 +1，否则老用户一段时间内仍会加载旧脚本。

## 质量保障

- **185 条自动化测试**：96 条求解器测试（正确性、回放一致性、边界、性能、批量上限与显眼度排序、难度分级与出题、两种粒度、Worker 消息协议）+ 89 条 UI 接线测试（含 Worker 正常应答、取消与异常分支、一步一格开关、逐格理由折叠、键盘可达性）
- **与朴素 DFS 对拍 220 道随机题**：解的数量完全一致，防止过度剪枝或漏解
- **粒度模式交叉验证**：`fast` 与 `teach` 两种模式的填格总数、终盘、排除步数量必须一致——拆分只改展示，不改推理
- **回放即验证**：每一步都可在盘面上复现，测试逐步核对填数合法性与理由完整性
- **CI 护栏**：GitHub Actions 自动执行类型检查、全量测试，并校验 `dist/` 与 `src/` 同步（含新增未跟踪的产物，防止改源码忘编译、或漏提交新产物就提交）
